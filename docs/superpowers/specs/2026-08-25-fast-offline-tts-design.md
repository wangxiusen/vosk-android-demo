# 轻量离线 TTS 与连续播放设计

## 目标

把第四个“任意文字口播”页面从 Kokoro 多语言模型改为中文、英文各自独立加载的轻量女声模型，并消除 sherpa 生成回调阻塞写入 `AudioTrack` 造成的句间卡顿。

## 已确认问题

- Kokoro 按句生成，生成回调是同步的。
- 当前回调使用 `AudioTrack.WRITE_BLOCKING` 播放整句，下一句必须等当前句播放结束后才开始生成。
- 华为 HMA-AL00 实测中文首段 PCM 约 3.6 秒，回调间等待约 5.9 秒；英文带标点时出现多次约 3.3～3.6 秒的生成等待。

## 方案

1. 使用 Apache-2.0 数据集训练的 `vits-icefall-zh-aishell3` 作为中文多女声模型，首期提供北方口音 SID 4 和南方口音 SID 122。
2. 使用公有领域 LJSpeech 数据训练、MIT 模型仓库发布的 `vits-piper-en_US-ljspeech-medium` 作为英文单女声模型。
3. 中文和英文均使用独立 VITS 模型，每次只加载当前语言模型。
4. sherpa 回调复制 PCM 到有界队列并立即返回；专用播放线程从队列持续写入 `AudioTrack`。
5. 播放线程按实际写入的 20ms PCM 帧计算嘴型；生成回调不直接更新动画。
6. 停止、关闭或切换语言时取消当前会话、唤醒等待线程并释放旧模型。

## UI 行为

- 进入页面默认加载中文模型。
- 切换语言时停止当前播放、禁用播放按钮并加载对应模型。
- 中文首期提供两个女声，英文提供一个明确标注的女声；保留声音选择控件和数据结构，后续新增语音模型时无需修改页面交互。
- 保留慢速、正常、快速三档语速。

## 验收标准

- JVM 单元测试、Android lint 和 debug 构建通过。
- 小米 2201122C（Android 15，arm64-v8a）能安装并打开第四页。
- 中英文带多个标点的文本均能完成口播，不崩溃，停止和语言切换有效。
- 日志能区分请求、模型加载、首个 PCM 入队、首次播放、生成结束、播放结束和 underrun。
- 对比旧实现记录首包延迟、句间停顿、总耗时和 PSS；若设备端数据未达到目标，保留准确结果，不伪称达标。

## 边界

- 不修改前三个 Demo 的业务行为。
- 不同时驻留两个 TTS 模型。
- 本阶段不实现在线 TTS、音色克隆或音素级口型。
